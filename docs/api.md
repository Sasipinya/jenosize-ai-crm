# API notes

Generated by reading the route handlers, `src/server/http.ts`, `src/server/errors.ts` and the Zod schemas in `src/lib/validation/` and `skills/crm-copilot/schema.ts`. Nothing here was invoked against a running server, so statuses come from the code paths. If you change a route, update this file.

## Conventions

- Success: `{ "data": ..., "requestId": "..." }`. Errors: `{ "error": { "code": "...", "message": "..." }, "requestId": "..." }` (`src/server/http.ts`).
- The only exception is the 401 from the route guard `src/proxy.ts`, which has no `requestId`, and NextAuth's own responses (`/api/auth/*`).
- Auth `session` = a logged-in NextAuth session (JWT, 8 h). Enforced twice: `src/proxy.ts` (401 `UNAUTHORIZED`, "Login required") and `withAuth` in each handler. There is **no role check** on any route except stage changes (below): any logged-in user, sales or admin, can call every other private route.
- Path ids are UUIDs (`z.uuid()`); anything else is a `VALIDATION_ERROR`.
- Lists return `{ items, total, page, pageSize: 20 }`.

### Error codes

| Code | HTTP | Typical cause |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Body is not JSON, Zod failure (`path: text; ...`), or a referenced record does not exist (Postgres FK 23503) |
| `UNAUTHORIZED` | 401 | No session, bad API key, bad LINE signature |
| `FORBIDDEN` | 403 | Non-admin reopening a won/lost lead |
| `NOT_FOUND` | 404 | Record does not exist |
| `CONFLICT` | 409 | Duplicate email, already-decided suggestion, duplicate message, erased contact, no LINE account |
| `RATE_LIMITED` | 429 | In-memory limiter (per server instance) |
| `INTERNAL` | 500 | Unexpected error (message hidden, logged without error text) or LINE adapter not configured |

### `GET /api/auth/[...nextauth]`, `POST /api/auth/[...nextauth]`

Both methods are the NextAuth handler (`src/app/api/auth/[...nextauth]/route.ts`, config in `src/server/auth.ts`). Credentials: `email`, `password` (1–200 chars), checked by `verifyCredentials`. The session carries `role` and `politeParticle`. Responses and errors are NextAuth's, not the `{ error }` shape. No rate limit on sign-in.

### `GET /api/leads`

Query (`leadListQuerySchema`): `q` (trimmed, ≤100, default empty), `page` (1–10000, default 1), `stage` (`new|qualified|proposal|won|lost`), `source` (`website|manual|line`), `owner` (UUID).
200: `{ data: { items: LeadRow[], total, page, pageSize: 20 } }`. Errors: `VALIDATION_ERROR`.

### `POST /api/leads`

Body (`leadCreateSchema`): `title` (1–200, required), `contactId` (UUID, required), `companyId` (UUID or null), `ownerId` (UUID or null; defaults to the caller), `valueThb` (integer 0–1,000,000,000; blank = 0). Source is always `manual`.
201: `{ data: <lead> }`. A `note` activity is written in the same transaction.
Errors: `VALIDATION_ERROR` ("Contact does not exist", or a missing company/owner).

### `GET /api/leads/:id`

200: `{ data: { lead, contact, company, ownerName, timeline } }` (timeline mixes activities and messages).
Errors: `NOT_FOUND` ("Lead not found").

### `PATCH /api/leads/:id`

Body (`leadUpdateSchema`): any of `title`, `companyId`, `ownerId`, `valueThb`; at least one key. `stage` is not editable here (unknown keys are dropped).
200: `{ data: <lead> }`, plus a `note` activity in the same transaction.
Errors: `NOT_FOUND`, `VALIDATION_ERROR`.

### `POST /api/leads/:id/stage`

Body (`stageChangeSchema`): `stage` (enum, required), `lostReason` (≤500; required when `stage` is `lost`).
200: `{ data: <lead> }` and a `stage_change` activity in the same transaction.
Errors: `VALIDATION_ERROR` ("A reason is required when marking a lead as lost", or "Lead is already <stage>"; the reason check runs before the lead lookup), `NOT_FOUND`, `FORBIDDEN` (only an admin can reopen a won or lost lead).

### `POST /api/leads/:id/activities`

Body (`activityInputSchema`): `type` (`note|call`), `text` (1–2000).
201: `{ data: <activity> }`. Errors: `NOT_FOUND`.

### `GET /api/contacts`, `POST /api/contacts`

GET query: `q` (≤100, matches name or email), `page`. 200: `{ data: { items, total, page, pageSize } }`.
POST body (`contactInputSchema`): `fullName` (1–200, required), `email` (valid, lowercased, ≤254, optional), `phone` (≤30), `companyId`, `ownerId` (UUID or null). 201: `{ data: <contact> }`.
Errors: `CONFLICT` ("A contact with this email already exists"), `VALIDATION_ERROR` (missing company/owner).

### `GET /api/contacts/:id`, `PATCH /api/contacts/:id`

GET 200: `{ data: <contact> }`. PATCH replaces the contact with the same body as POST; 200: `{ data: <contact> }`.
Errors: `NOT_FOUND`, `CONFLICT` (duplicate email, or "This contact's data was erased and cannot be edited"), `VALIDATION_ERROR`.

### `GET /api/companies`, `POST /api/companies`

GET query: `q` (name search), `page`. 200: `{ data: { items, total, page, pageSize } }`.
POST body (`companyInputSchema`): `name` (1–200, required), `industry` (≤100), `website` (≤200, must start with `http://` or `https://`), `size` (≤50). 201: `{ data: <company> }`. Errors: `VALIDATION_ERROR`.

### `GET /api/companies/:id`, `PATCH /api/companies/:id`

GET 200: `{ data: <company> }`. PATCH replaces the company with the same body as POST; 200: `{ data: <company> }`. Errors: `NOT_FOUND`, `VALIDATION_ERROR`.

### `POST /api/public/leads`

Public intake for the website form. Checks in order: rate limit (5 per 60 s per IP, first `x-forwarded-for` value), then `x-api-key` equal to `LEAD_INTAKE_API_KEY` (constant-time compare), then the body.
Body (`websiteLeadSchema`): `fullName` (1–200), `email` (valid, ≤254), `message` (1–2000), `phone` (≤30), `companyName` (≤200), `companyWebsite` (≤500, **honeypot**: a filled value returns the same 201 and creates nothing).
201: `{ data: { accepted: true } }`. Creates (or reuses by email) a contact and a `website` lead with a `note` activity in one transaction. No dedupe: each valid submission is a new lead.
Errors: `RATE_LIMITED`, `UNAUTHORIZED` ("Invalid API key"), `VALIDATION_ERROR`, `INTERNAL`.

### `POST /api/ai/suggest`

Body: `{ "leadId": "<uuid>" }` (strict, no other keys). Rate limit: 10 per 60 s per user.
200: `{ data: { suggestion, cached } }`. Returns the cached suggestion while no newer event exists and the prompt version is unchanged; otherwise creates a `pending` one. Writes only the `ai_suggestions` row, never lead data. LLM failures are not errors: the suggestion comes back with `source: "fallback"`.
Errors: `VALIDATION_ERROR`, `RATE_LIMITED`, `NOT_FOUND` ("Lead not found").

### `POST /api/ai/suggestions/:id/decision`

Body (`aiDecisionSchema`, discriminated on `action`):

| `action` | Fields | Effect |
| --- | --- | --- |
| `accept` | none | Lead score = AI score + quick-reply boosts (each button once), clamped 0–100; writes an `ai_accepted` activity |
| `edit` | `finalOutput` (the suggestion schema: `summary` 1–600, `score` 0–100, `scoreReasons` 1–5, `nextBestAction` {`type` `call|line_reply|send_proposal|wait|close_lost`, `detail`, `dueInDays` 0–60}, `draftReply` or null, `confidence` `low|medium|high`, `missingInfo` ≤5) | Saves the typed score as-is (a draft-only edit behaves like accept); writes the same activity |
| `dismiss` | `rejectReason` (`wrong_facts|wrong_tone|missing_info|wrong_action`), `rejectNote` (≤500), both optional | Only the suggestion row changes |

200: `{ data: <ai_suggestions row> }`. All writes of one decision are in one transaction, guarded by `status = 'pending'`.
Errors: `NOT_FOUND` (suggestion or lead), `CONFLICT` ("Suggestion was already <status>", or the lead is already won/lost so the suggestion can only be dismissed), `VALIDATION_ERROR` ("No changes were made; use accept instead").

### `GET /api/health`

Public probe for uptime checks (`src/app/api/health/route.ts`, `src/server/services/health.ts`). Flat JSON, **not** the `{ data, requestId }` envelope. Never cached (`Cache-Control: no-store`). Exposes no secret, no PII and no error text.

200 or 503: `{ "status": "ok|degraded|error", "db": "ok|error", "ai": { "adapter": "claude|mock", "model": "...", "configured": true, "simulatedDown": false }, "line": { "adapter": "real|mock", "configured": true }, "version": "<7-char git sha>|null" }`

- `db`: a `select 1` plus the `simulate_ai_down` read, together under a 3 s timeout (the query is not cancelled). If it fails (or `DATABASE_URL` is unset), the response is **503** with `status: "error"`, `db: "error"` and `ai.simulatedDown: null`.
- `status`: `degraded` (still 200) when a real adapter is selected without its key/token (for LINE, access token and channel secret); `ok` otherwise. `simulatedDown` (the `simulate_ai_down` switch) is reported but does not change `status`.
- `version`: first 7 characters of `VERCEL_GIT_COMMIT_SHA`, `null` when absent.

### `POST /api/webhooks/line`

Public to the proxy, authenticated by signature. `maxDuration` 30 s.
Order: LINE adapter configured? (else `INTERNAL`), read the raw body as text, verify `x-line-signature` (HMAC-SHA256 base64 of the raw body with `LINE_CHANNEL_SECRET`, `timingSafeEqual`), parse JSON, validate (`events` ≤100, each with `type` and `webhookEventId` 1–100 chars).
Each event is inserted into `line_events` with `ON CONFLICT (webhook_event_id) DO NOTHING`; a duplicate is skipped, except that an event that previously failed is claimed once so a redelivery can reprocess it. New events are processed after the response; a processing failure is stored in `line_events.error` and does not change the response.
200: `{ data: { received: <n> } }`.
Errors: `UNAUTHORIZED` ("Invalid signature", nothing stored; also when the secret is unset or a placeholder), `VALIDATION_ERROR`, `INTERNAL` ("LINE is not configured", only with `LINE_ADAPTER=real` and no token).

### `POST /api/messages`

Body (`sendMessageSchema`, strict): `leadId` (UUID), `body` (trimmed, 1–1000). `maxDuration` 30 s.
Approves and sends in one call: the message is stored as `approved` with a note activity and a fresh `retry_key`, pushed with up to 3 attempts (backoff on 5xx/timeout, stop on 4xx), then recorded as `sent` (plus a `message_sent` activity) or `failed`.
201: `{ data: { id, status, attempts } }`. `status` may be `failed` and the response is still 201: check the field.
Errors: `NOT_FOUND`, `CONFLICT` ("This contact has no LINE account to send to"; "This exact message was already sent to this lead in the last minute"; "Message state changed while sending"), `INTERNAL` ("LINE is not configured").

### `POST /api/messages/:id/retry`

No body. Re-sends a `failed` outbound message with the same `retry_key`.
200: `{ data: { id, status, attempts } }`.
Errors: `NOT_FOUND` (message missing or not outbound), `CONFLICT` ("Only a failed message can be retried"; no LINE account; duplicate within a minute; "Message was already retried"), `INTERNAL`.

## Known gaps

- No role checks beyond stage reopening: any logged-in user can retry any message or edit any record.
- The rate limiter is in memory per instance and trusts the first `x-forwarded-for` value.
- There is no API to erase a contact (the `PATCH /api/contacts/:id` guard on erased contacts exists, but nothing sets `erased_at`; see the README).
